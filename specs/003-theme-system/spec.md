# Feature Specification: 白色与黑色主题系统

**Feature Branch**: `main`

**Created**: 2026-08-18

**Status**: Draft

**Input**: User description: "添加一个页面主题组件，用于切换白色/黑色主题，同时抛弃当前的主题。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 切换白色与黑色主题 (Priority: P1)

管理员可以在登录页和控制台顶部切换白色或黑色主题，整个页面立即使用所选配色。

**Why this priority**: 主题切换是本功能的核心用户价值，必须在登录前后都可用。

**Independent Test**: 在登录页切换主题，确认背景、文字、卡片、输入框和按钮同时变化；登录后再次切换，确认控制台全部区域同步变化。

**Acceptance Scenarios**:

1. **Given** 页面使用白色主题，**When** 用户点击主题切换组件，**Then** 页面立即切换为黑色主题。
2. **Given** 页面使用黑色主题，**When** 用户再次点击切换组件，**Then** 页面立即切换为白色主题。
3. **Given** 用户尚未登录，**When** 打开登录页，**Then** 主题组件仍然可见且可操作。

---

### User Story 2 - 记住主题选择 (Priority: P1)

用户刷新页面或重新打开管理台后，系统继续使用上一次主动选择的主题。

**Why this priority**: 如果每次刷新都恢复默认主题，切换功能会造成明显干扰。

**Independent Test**: 选择黑色主题后刷新页面，确认仍为黑色；切换白色后再次刷新，确认仍为白色。

**Acceptance Scenarios**:

1. **Given** 用户选择黑色主题，**When** 页面重新加载，**Then** 黑色主题在页面首次可见时生效。
2. **Given** 用户从未主动选择主题，**When** 首次打开页面，**Then** 系统使用设备配色偏好作为初始选择。
3. **Given** 浏览器无法读取已保存主题，**When** 页面加载，**Then** 系统使用安全默认主题且页面仍可操作。

---

### User Story 3 - 使用全新的中性视觉体系 (Priority: P2)

管理员看到的是统一、清晰的白色和黑色管理台，而不是原有绿色霓虹视觉主题。

**Why this priority**: 用户明确要求抛弃当前主题，因此不能只替换少量颜色变量。

**Independent Test**: 对登录页、机器人连接、群聊、消息、发送表单和审计面板进行视觉检查，确认原有绿色渐变、霓虹边框和扫描线效果不再出现。

**Acceptance Scenarios**:

1. **Given** 任一主题，**When** 用户浏览主要面板，**Then** 所有区域使用统一的中性色、间距、圆角、边框和阴影体系。
2. **Given** 白色主题，**When** 用户查看文本和交互控件，**Then** 内容在浅色背景上具有清晰对比度。
3. **Given** 黑色主题，**When** 用户查看文本和交互控件，**Then** 内容在深色背景上具有清晰对比度且不会出现纯黑内容丢失。

### Edge Cases

- 浏览器禁用或限制本地存储时，主题切换仍应在当前页面会话中工作。
- 保存值不是受支持主题时，系统必须忽略该值。
- 主题切换不能清除管理员令牌、消息、群选择或表单输入。
- 快速连续点击主题按钮时，最终主题状态必须与按钮显示一致。
- 二维码、状态颜色、错误提示和 disabled 状态在两个主题下都必须可辨识。
- 移动端窄屏下主题按钮不能遮挡品牌、退出或刷新操作。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供可复用的页面主题上下文和主题切换组件。
- **FR-002**: 系统必须支持且仅支持白色和黑色两个主题。
- **FR-003**: 主题组件必须同时出现在登录页和已登录控制台。
- **FR-004**: 切换主题必须立即更新完整页面，不得要求刷新。
- **FR-005**: 系统必须保存用户主动选择的主题。
- **FR-006**: 首次访问且无保存值时，系统必须尊重设备的深浅色偏好。
- **FR-007**: 无效或不可读取的保存值不得阻止页面加载。
- **FR-008**: 页面根节点必须暴露当前主题状态，供所有组件共享语义颜色。
- **FR-009**: 主题切换组件必须提供清晰的可访问名称和当前状态。
- **FR-010**: 登录、绑定、群聊、消息、发送、错误、空状态和审计区域必须全部使用新主题变量。
- **FR-011**: 原有绿色霓虹、径向渐变、扫描线和专用 mint 色体系必须被移除。
- **FR-012**: 二维码前景色必须随主题变化并保持透明背景。
- **FR-013**: 两个主题必须为成功、警告和错误状态提供一致且可区分的语义色。
- **FR-014**: 主题切换不得改变业务状态、鉴权状态或 API 行为。

### Key Entities

- **Theme**: 当前页面配色，取值为 `light` 或 `dark`。
- **Theme Preference**: 用户浏览器中保存的最近主动选择。
- **Theme Context**: 向整个 React 组件树提供当前主题与切换行为的共享状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户一次点击即可在白色和黑色主题之间切换。
- **SC-002**: 主题切换后 100 毫秒内所有可见区域完成配色更新。
- **SC-003**: 刷新页面后，100% 恢复最近一次有效主题选择。
- **SC-004**: 登录页和控制台的所有主要区域均通过两个主题的浏览器视觉检查。
- **SC-005**: 现有前端组件测试、ESLint 和生产构建全部通过。
- **SC-006**: 新主题组件自动化测试覆盖初始主题、切换和持久化行为。
- **SC-007**: 原有主题中的绿色背景渐变和霓虹视觉规则在最终全局样式中不再存在。

## Assumptions

- 主题偏好按浏览器保存，不在服务端账户之间同步。
- 系统只提供白色和黑色，不增加第三种“跟随系统”可选按钮；系统偏好仅用于首次默认值。
- 业务组件结构和 API 行为保持不变，本功能聚焦主题基础设施和完整视觉重构。
